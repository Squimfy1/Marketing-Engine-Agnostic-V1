# Marketing Engine — Architecture

A brand-agnostic content engine: one engine serves many clients, each described
by per-client files in a vault. Generation runs through Claude via your **Claude
Code login** (no API key).

## Two halves

- **The Engine** — Python in `src/marketing_engine/`, committed, generic. Knows
  nothing about any client.
- **The Vault** — `vault/`, a folder of **Obsidian-style markdown + YAML**, one
  folder per client. **Gitignored** (it's client data). All client-specific
  behaviour lives here.
- **The Dashboard** — `web/dashboard.html`, served by the engine (`engine serve`).

To change a client → edit vault files. To change the engine → edit `src/`.

## The vault layout

```
vault/
├── _shared/                         applies to every client
│   ├── rules/                       anti-AI writing rules (WRITING_RULES, BANNED_PATTERNS, CONTENT_STRUCTURES)
│   └── platforms/short-posts.md     short-post format guidance
└── tenants/<account>/brands/<client>/
    ├── brand.yaml                   identity, voice, narrative, model tiers (YAML)
    ├── _rules/                      always-on brand rules — ALL inlined into the system prompt
    │   ├── brand-profile.md           human-authored profile (audience/voice/thesis)
    │   ├── guardrails.md              never-do list + confidentiality
    │   ├── _core.md                   operational rules
    │   └── strategy.md                AUTO (engine distill): the universal strategy profile —
    │                                    business principles · personas · customer narratives ·
    │                                    key ideas · direction · avoid. The filter scores against it.
    ├── _sources/   🔒               raw call transcripts. FIREWALLED — only `distill`
    │                                 reads them; generation can never quote them.
    ├── _kb/                         public material the agent may read (litepaper, proof-points.md [auto])
    ├── _outputs/                    saved drafts (markdown + YAML frontmatter)
    ├── _memory/                     LAB_LEARNINGS.md (edit learnings)
    └── _design/tokens.yaml          brand colours/fonts (for image briefs)
```

Human-owned files vs `distill`-owned (auto, "do not hand-edit"): `strategy.md`
and `_kb/proof-points.md` are regenerated by `engine distill`; everything else in
`_rules/` is yours. (You *may* hand-edit `strategy.md` to correct it — a re-distill
overwrites it.)

## Engine code, by job

Folders mirror the systems diagram — each box is one zone:

| Diagram box | Area | Files | Job |
|---|------|-------|-----|
| Rules / Who | **tenant/** | `registry.py`, `schema.py`, `scaffold.py` | find clients (scan vault); `new-brand`, `ingest` |
| Rules / Who | **brand/** | `schema.py`, `assembler.py` | BrandConfig; build the per-client system prompt (the agnostic seam) |
| Agent Harness | **harness/** | `engine.py`, `prompts.py` | the brain: orchestrates generate / options / image briefs; prompt templates |
| Content Generation | **content/** | `strategy.py`, `filter.py`, `distill.py`, `validate.py`, `platforms.py`, `postprocess.py` | the universal strategy schema; the strategy filter; distillation; the Haiku quality gate; platform format; parsing |
| LLM | **sdk/** | `client.py`, `isolation.py`, `models.py` | the ONLY place that talks to Claude; the brand-isolation + `_sources` firewall hook; model tiers |
| Obsidian Memory / KB | **vault/** | `layout.py`, `fs_adapter.py`, … | the ONLY place that touches files; path conventions |
| Integrations + Scraper | **inputs/** | `convert.py` (PDF→text) | feeds into a brand's vault; MCP connectors + scraper land here |
| Image Generation | **image/** | `recommend.py` | recommend image approaches + options → Claude Design instructions |
| Frontend | **server/** | `app.py`, `routes.py`, `bundle.py` | the dashboard HTTP backend (`/api/*`) |
| — | **tools/** | `learnings.py`, `output_tools.py`, `memory_tools.py` | the writers (drafts, learnings, memory notes) |
| — | **cli.py** | | `run` `serve` `new-brand` `ingest` `distill` `list` |

Two invariants: **only `sdk/` imports Claude; only `vault/` touches files.** So
the rest is testable offline with a fake model.

## How a short post is made

1. **Ideas** — `engine.generate_options()` → Haiku, single-shot, brainstorms a few
   extra idea briefs. The system prompt is assembled from `brand.yaml` +
   all `_rules/*.md` + `_shared` writing rules.
2. **Filter** — `content/filter.py` → one cheap Haiku call scores each idea against
   the brand's `strategy.md` (business principle × customer narrative). Survivors
   carry their tags; weak ones are dropped. Fails open if there's no strategy yet.
3. **Pick one → full post** — `engine.generate()` → Opus writes the post (may read
   `_kb/`, blocked from `_sources/`).
4. **Clean** — `postprocess.clean_copy()` strips em-dashes.
5. **Gate** — `content/validate.py` → Haiku checks one-idea / on-narrative /
   no-crypto / single-CTA, with ONE bounded retry on failure.
6. **Images** — `image/recommend.py` → recommend approaches + 3 options
   (library / real photo / generated); pick one → `engine.generate_image_brief()`
   writes the Claude Design instructions for that choice.
7. **Save** — `tools/learnings.py` writes a dated note to `_outputs/` + a learning
   to `_memory/` (manually triggered; the learning loop is human-verified).

Model tiers: Haiku for ideas + the filter + the gate; Opus for the real draft +
distillation. Prompt caching keeps the stable system prompt cheap.

### Why the filter is agnostic
`content/strategy.py` defines `STRATEGY_SECTIONS` — the same three dimensions
(business principles, customer personas, customer narratives) for *every* brand.
`distill` fills them from that brand's uploaded calls; `filter` reads them back by
key. Neither the filter nor the engine ever names a brand — Denario works because
its `strategy.md` is filled in, and any other company works the same way once
theirs is. The schema is the contract; the LLM is the parser; the vault holds the
fill.

## Onboarding a new client

```
engine new-brand -t <account> -b <client>
engine ingest <transcripts...> -t <account> -b <client> --sources   # -> _sources/ (firewalled)
engine ingest <public docs...> -t <account> -b <client>             # -> _kb/
engine distill -t <account> -b <client>                             # writes key-ideas.md + proof-points.md
# review the written files, edit brand.yaml (identity/voice/narrative), then generate
engine serve   # dashboard at http://127.0.0.1:8765/
```

## Run / test

```
python3.12 -m venv .venv && source .venv/bin/activate && pip install -e ".[dev]"
pytest                                  # full offline suite (fake model, no network)
VAULT_ROOT=./vault engine serve         # live dashboard (uses your Claude Code login)
```
